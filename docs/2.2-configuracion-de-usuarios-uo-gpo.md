# Configuración de usuarios, unidades organizativas y directivas de grupo
El siguiente paso consiste en estructurar el dominio creando usuarios, unidades organizativas y directivas de grupo.

He ido a la ventana de Usuarios y equipos de Active Directory desde el **Panel > Herramientas**  
![Herramientas](/img/herramientas.png)

![Usuarios y equipos de AD](/img/usuarios-y-equipos-ad.png)

**Unidades organizativas (OUs):** He creado unidades organizativas por departamentos. Dentro de estas están los usuarios, y tienen aplicadas directivas de grupo.  
![Nueva UO](/img/nueva-uo.png)

- **IT:** Contiene el usuario **soporte.it** del departamento IT
![Departamento IT](/img/it.png)

- **RRHH:** Contiene los usuarios **maria.rrhh** y **david.rrhh** del departamento RRHH
  ![Departamento RRHH](/img/rrhh.png)
  
  ![Usuarios del departamento de RRHH](/img/rrhh-2.png)

- **Finanzas:** Contiene la cuenta de servicio **sql.finanzas** del departamento Finanzas:
![Departamento Finanzas](/img/finanzas.png)

  Para que este usuario actúe como una cuenta de servicio real, le he asignado un SPN (Service Principal Name) asociado al servicio de Microsoft SQL Server,
  con el comando ``setspn -S MSSQLSvc/srv-lab.server.local:1433 sql.finanzas``
  ![Comando setspn](/img/setspn.png)
  
  ![Comando setspn](/img/setspn-2.png)
  
  Este comando le indica al AD que la cuenta sql.finanzas es la identidad bajo la que se ejecuta el servicio SQL Server en nuestro servidor **srv-lab.server.local:1433**
  
  Permite que los clientes utilicen la **autenticación Kerberos** cuando se conectan a SQL Server en lugar de utilizar NTLM,
  lo que es ideal para probar ataques de Kerberoasting.

**Política de grupo (GPO):** Inicialmente, he creado una GPO para que Windows registre los ataques en el visor de eventos y Wazuh los pueda detectar.
- GPO **'Auditoría avanzada'** a nivel de dominio: Dentro de esta GPO, he ido a la ruta **Configuración del equipo > Directivas > Configuración de Windows >
Configuración de seguridad > Configuración de directiva de auditoría avanzada > Directivas de auditoría**
  - **Configuraciones activadas:**
    - **Inicio y cierre de sesión:** Auditar inicio de sesión
      ![Auditar inicio de sesión](/img/auditar-inicio-de-sesion.png)

    - **Inicio de sesión de cuentas:** Auditar servicio de autenticación Kerberos
      ![Auditar servicio de autenticación Kerberos](/img/autenticacion-kerberos.png)

    - **Seguimiento detallado:** Auditar creación de procesos
      ![Auditar creación de procesos](/img/auditar-creacion-procesos.png)

      **'Incluir línea de comandos en eventos de creación de procesos'** habilitado (Configuración de equipo > Directivas >
      Plantillas administrativas > Sistema > Auditar creación de procesos):
      ![Incluir línea de comandos en eventos de creación de procesos](/img/linea-de-comandos-creacion-de-procesos.png)  
      Esta opción permite registrar los parámetros de los comandos que ejecutan los procesos.
