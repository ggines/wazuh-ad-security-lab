# Instalación de Suricata
Para detectar ataques de red con mayor detalle, he instalado el IDS/IPS Suricata en Windows Server siguiendo estos pasos:

He instalado la biblioteca [Npcap](https://npcap.com/dist/npcap-1.88.exe) para que Suricata pueda capturar y analizar el tráfico:
![npcap setup](/img/npcap-setup.png)

He instalado Suricata mediante el instalador para Windows descargado desde [Download - Suricata](https://suricata.io/download/):
![suricata setup](/img/suricata-setup.png)

Después de instalar Suricata, he abierto el archivo de configuración **C:\Program Files\Suricata\suricata.yaml** para editar estos valores:
- **HOME_NET** → 10.0.1.10 (Se indica la red de confianza. Suricata toma esta red como de confianza para no generar alertas de los eventos que se generen en
  esta red. En este caso, como queremos que sí genere alertas, únicamente he indicado la IP de la propia máquina Windows Server, para que alerte de
  cualquier evento que se genere fuera de esta IP).
- **rule-files** →
  - He comentado las líneas de las reglas que no están en el directorio **C:\Program Files\Suricata\rules** para evitar errores.
  - He descomentado las líneas de las reglas que sí están en el directorio **C:\Program Files\Suricata\rules**
  - He descargado varios archivos de reglas [Proofpoint Emerging](https://rules.emergingthreats.net/open/suricata-7.0.3/rules/)
    y los he guardado en el directorio **C:\Program Files\Suricata\rules**  
    Las [Emerging Rules](https://rules.emergingthreats.net/open/) son reglas dinámicas que se mantienen actualizadas para cubrir nuevas vulnerabilidades.
    En este caso, he descargado las reglas:
    - **botcc.rules** → Bloqueo de servidores de comando y control (C2)
    - **ciarmy.rules** y **dshield.rules** → Listas de reputación IP con atacantes activos y maliciosos conocidos.
    - **emerging-scan.rules** → Detecta escaneos de puertos y reconocimiento de red
    - **emerging-icmp.rules** → Detecta tráfico ICMP
    - **emerging-dns-rules** → Detecta ataques de DNS y consultas de dominios maliciosos
    - **emerging-dos.rules** → Identifica ataques de Denegación de Servicio
   
    Existen muchas otras reglas, pero para este caso estas son suficientes.
    ![Proofpoint Emerging Threat Rules](/img/proofpoint-emerging-threat-rules.png)

    ![suricata.yaml](/img/rule-files1.png)

    ![suricata.yaml](/img/rule-files2.png)

Después de aplicar estos cambios en el archivo de configuración **suricata.yaml**, he comprobado que no hayan errores ejecutando el comando
``suricata.exe -T -c "C:\Program``
![Comando suricata](/img/comando-suricata.png)

Tras comprobar que no hay errores, he ejecutado el comando ``suricata.exe -c "C:\Program Files\Suricata\suricata.yaml" -i 10.0.1.10`` para iniciar Suricata.
En el comando se indica el archivo **suricata.yaml** para que use esa configuración y la IP de la propia máquina.
![Comando suricata](/img/comando-suricata2.png)

Para que Suricata se inicie cada vez que iniciemos el sistema, he añadido una tarea en el programador de tareas:
<p>
  <img src="/img/suricata-programador-tareas.png" alt="Programador de tareas" width="50%">
</p>

<p>
  <img src="/img/acciones-programador-tareas.png" alt="Acción del programador de tareas" width="60%">
</p>

La tarea consiste en ejecutar el comando anterior al iniciar el sistema, con los privilegios más altos y sin importar si el usuario inició sesión.

De esta manera, no es necesario estar ejecutando el comando para iniciar Suricata cada vez que iniciemos el sistema.
